# Coda App — Architecture

What exists in the code (M1 foundation, M2 browse and the M4 experience slice, 2026-11-05). Proposals are marked as such.

```text
React UI ──invoke("intent", {intent})──▶ commands.rs ──mpsc(256)──▶ engine.rs (one Tokio task)
   ▲  invoke("snapshot")                                             │ Engine: Player + resolve::dispatch,
   │                                                                 │   Library + scan state, scrobble listen,
   └── events: snapshot / progress / visualizer ◀── Sink (lib.rs) ◀──┤   notices, save revision, emission
React UI ──invoke("local_*" / "navidrome_*")──▶ browse/commands.rs ──▶ BrowseHandle (shared, read-only for commands):
                                                  Library (RwLock, engine writes) + current Client, each with a generation
                                                                     │ Io: PlaybackHandle (mpv), scan rx, ping,
webview <img src="coda://localhost/cover/<token>/small">             │   Scrobbler, Saver (blocking writes), 50 ms tick
   └──▶ cover.rs (URI scheme) ──▶ coda_core::cover::load + disk cache
```

## Crates
- `crates/coda-core` (lib `coda_core`): Coda's engine, vendored. Additions for the GUI in M1: `cover::load` (async, one cover at a key and size; `spawn_load` now uses it), `cover::encode_jpeg`, `Library::track_id_by_path`, `logging::init_logging_at(path)`, `Drop for PlaybackHandle` (SIGTERM to a still-running mpv), and on Linux `PR_SET_PDEATHSIG` in `mpv_command`. In M4: `config_writer::{Preferences, write_preferences, read_preferences}` (music folder, `scrobble`, `[ui] cover_art`; `[navidrome]` kept as is, same backup/atomic-write rules), `playback::mpv::process::{find_program, default_program, FALLBACK_DIRS}` (`spawn_backend` looks for mpv on `PATH`, then `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`), and `Player::set_volume` now works while stopped (the request becomes the shown and saved preferred volume; mpv accepts volume while idle). In M2: `Track::album_id`/`artist_id` (Navidrome ids for navigation, set from `albumId`/`artistId`; not saved in the session), `cover_art` on Navidrome `Artist`/`Album`/`Playlist` and `artist_id` on `Album`, `TagIndex::album_of`/`artist_of` (a local track's album/artist) and `TagIndex::search` (artists/albums by name).
- `src-tauri` (`coda-app`, lib `coda_app_lib`): the backend.

## Backend modules (`src-tauri/src/`)
- `lib.rs`: Tauri builder; registers the `coda` URI scheme, spawns the engine in `setup`, manages `EngineHandle`, and owns the quit sequence.
- `bootstrap.rs`: `Paths` (GUI files under `<Coda state dir>/coda-app/`: `session.json`, `coda-app.log`, `media/` for the media-controls cover; Coda's cover cache is shared; `tui_session` = the TUI's `state.json`), `init_logging`, and `start()`: `Config::load(cli_from_process(), Env::from_process())` (`CODA_MUSIC_DIR` honoured like the TUI), password + `navidrome::Client` (`config::navidrome_client`), `playback::spawn_backend()` and the session restore, run concurrently. Restore first imports the TUI's session once when the GUI has none: `session::read_valid` (coda-core; non-blocking open, regular files only, 16 MiB cap, decoded, never renames) and only a valid one is copied (`create_new`, `O_NOFOLLOW`, 0600, renamed into place); a `coda-app/.tui-imported` marker records the attempt (valid or not), so it never happens again, even after the GUI's own session is set aside. The TUI's file is never modified. Every failure becomes a `ProblemDto` (`noConfig`, `config`, `mpvMissing`, `playback`, `navidrome`); nothing panics.
- `engine.rs`: the actor.
  - `Engine` is the synchronous core: `start(sources, playback_problem, restored)`, `handle_intent`, `handle_playback_event`, `handle_scan_event`/`scan_closed`, `handle_ping`, `handle_scrobble_failure`, `tick`; outputs `Vec<PlaybackCommand>` plus queued visualizer frames and scrobble requests. Every player call goes through `resolve::dispatch` (which also re-announces the gapless next after queue edits), then `take_messages()` become notices and the save revision is checked.
  - `run` is the loop: `select!` over startup completion, intents, playback events, scan events, the Navidrome ping, the first scrobble failure, and a 50 ms tick (notice expiry, session-save polling). After each branch it flushes: visualizer frames at once, scrobbles to the worker, a `snapshot` event if anything visible changed, `progress` if the position changed and ≥100 ms passed.
  - Startup runs as its own task, so the UI gets a `starting` snapshot immediately (a password command or keychain prompt can take a while). Intents other than visualizer visibility and notice dismissal are ignored until `ready`.
  - Session: revision based (`Player::revision`), saved 2 s after the last change, one blocking write at a time; restore never auto-plays; final save at exit bounded to 2 s. The GUI has its own session file, so it never overwrites the TUI's queue.
  - Scrobbling: `listen_started`/`listen_progressed` ported from the TUI's `App` (no client swap yet, so no `unscrobbled_load`).
  - Visualizer: `SetVisualizer(true)` only while the UI says a view is visible (`setVisualizerVisible`), never after `VisualizerUnavailable`; frames are forwarded raw only for `audible_load` while playing. Smoothing/decay is the UI's job (none yet: no visualizer view in M1).
  - Live settings (`engine/settings.rs`, `Msg::Settings` → `Engine::apply_settings`, refused until `ready`): `Client` (port of the TUI's `swap_client`: new `CoverService` client, which forgets remote cover tokens and mixes a new generation into new ones so the webview never shows the old server's cached art; queue resent; listen dropped and the current load marked `unscrobbled_load`; scrobble state reset; `Player::client_changed` re-announces/reloads remote entries signed by the old client; the loop pings the new client and replaces the scrobbler), `MusicDir` (new `Library`, `Scanning`, the loop starts a new scan; dropping the old receiver ends the old scan), `CoverArt` (URLs on/off, queue resent), `Scrobble` (needs a client; a track already playing is not reported halfway). `Client`/`MusicDir` clear `noConfig`/`config` problems (onboarding).
  - `Client` and `MusicDir` also update the `BrowseHandle` (new client / new library, each a new generation; the queue is resent so local ids follow the new library).
  - Shutdown (`EngineHandle::shutdown`): `phase = shuttingDown` snapshot, wait ≤3 s for a still-running startup (else abort and await it, so a `PlaybackHandle` it holds is dropped and mpv terminated), final save, `PlaybackHandle::shutdown(2 s)`, reply.
- `browse.rs` (+ `browse/`): everything the browse views read.
  - `BrowseHandle` (managed Tauri state, cheap `Clone`): the local `Library` behind a `std::sync::RwLock` plus a *library generation*, and the current Navidrome `Client` plus a *client generation*. The engine is the only writer: `replace_library` (start, and a music-folder change in settings) bumps the library generation, scan batches go through `update_library` (one short write per batch), `set_client` publishes the client at start and on every settings client swap (bumping the client generation). Both generations are in the snapshot (`browse: {library, server}`); the UI clears its Navidrome cache and resets a stack holding that source's views when one changes. Commands never touch `Player` or the engine channel.
  - Local commands run their read on a blocking thread (`BrowseHandle::local`), so long reads (search, a 5,000-album list) never run on the engine task; the engine waits at most one such read for its next batch write.
  - Navidrome commands go through `BrowseHandle::fetch`: at most `MAX_CONCURRENT_FETCHES` (4, Coda's) requests at once (a semaphore); a result that arrives after the client generation changed is dropped as `stale`. Failures are logged with `Error::detail()` and returned as their `Display` text (never credentials).
  - `browse::track_dto` builds every `TrackDto` (queue and browse), so local tracks are named the same way everywhere.
  - `browse/dto.rs` (browse DTOs and `BrowseError {kind, message}`), `browse/local.rs` (queries over a `LocalView`), `browse/navidrome.rs` (queries through the client), `browse/commands.rs`, `browse/tests.rs`.
- `dto.rs`: serde DTOs (camelCase), mirrored by hand in `src/lib/types.ts`.
- `commands.rs`: `intent(intent)` and `snapshot()`; the browse commands live in `browse/commands.rs`.
- `settings.rs`: the Settings view's and onboarding's commands (below). Reads the file with `config::read_for_setup` + `config_writer::read_preferences` (never resolves the password); ownership like the TUI's settings: a server Coda wrote (keychain) can be edited/disconnected, one set outside Coda (`CODA_NAVIDROME_*`, hand-written `password`/`password_command`) is shown and left alone; `onboarding::navidrome_blocked_by` blocks saving a server. Saves go through `setup_actions` (ping first, then keychain, then config; old keychain entry removed) and `config_writer::write_preferences`, on blocking threads, one at a time (`SettingsLock`, which the quit sequence awaits ≤3 s before the engine shutdown); only then `EngineHandle::apply_settings`. `ServerInput` (the typed password) has a redacted `Debug`; no DTO carries a password. The folder picker is `tauri-plugin-dialog` used from Rust (no JS plugin API, no capability).
- `media.rs`: OS media controls (`souvlaki`, zbus MPRIS backend on Linux, `MPNowPlayingInfoCenter` on macOS). `TauriSink` feeds it every snapshot/progress; `Publisher` (pure, tested) publishes metadata on a track change, status on a change, the position on the first report, a jump >1.5 s or every 5 s while playing. Covers: loaded through `CoverService::image_for_url`, written as `<state>/coda-app/media/cover-<n>.jpg` (0600, older ones removed) and published as `file://`. Events → intents (`Play`/`Pause` only toggle when needed, seek ±10 s, set position, volume; `Raise` focuses the window; `Quit` takes the normal quit path). Every souvlaki call runs on the main thread (`run_on_main_thread`, controls in a main-thread `thread_local`); a failure to create them is logged and the app runs without. Dropped at `RunEvent::Exit`.
- `cover.rs`: `CoverService` (registry, current client, small/large disk caches, 4 concurrent loads) and the protocol handler.

## IPC contract
- Commands: `intent({ intent })`, `snapshot()` → full `Snapshot` (queue included). Settings (each rejects with a message to show): `settings_get()` → `Settings` (`configPath`, `musicDir` as written, `musicDirEnv`, `server` = `notConfigured` | `coda{url, username}` | `outside{url, username, by}`, `serverBlockedBy`, `scrobble`, `coverArt`, `problem`), `settings_test_server({server})`, `settings_save_server({server})`, `settings_disconnect()`, `settings_pick_folder()` → path or `null`, `settings_set_music_dir({folder})` (refused while `CODA_MUSIC_DIR` is set), `settings_set_options({coverArt?, scrobble?})`, `onboarding_finish({musicDir?, server?})`. `server` is `{url, username, password}`.
- Events:
  - `snapshot` (coalesced on the 50 ms tick, only when the snapshot differs from the last one sent). `queue` is `null` when the entry list (by key) did not change, so a 10,000-entry queue is not resent on every status change; the UI keeps its last queue. `browse: {library, server}` carries the browse generations. A `snapshot()` call resets this, so the next event carries the queue again (the UI applies the command's result only if no event arrived first).
  - `progress`: `{ positionMs, durationMs }` of the heard track, ≤10/s.
  - `visualizer`: `{ levels: [l, r], bands: [7 × number|null] }`, ≤30/s, only while enabled.
- `Intent` (tagged by `type`): `togglePause`, `next`, `previous`, `seekTo{seconds}`, `seekBy{seconds}`, `setVolume{volume}`, `cycleRepeat`, `playEntry{key}`, `removeEntry{key}`, `clearQueue`, `setVisualizerVisible{visible}`, `playTracks{tracks, start?, shuffle?}`, `enqueue{tracks, next?}`, `dismissNotice{id}`, `shuffleLibrary` (local "Shuffle all": every scanned track shuffled, a random sample at `MAX_QUEUE_LEN`, as in Coda).
- Browse commands (all async, `Result<DTO, BrowseError>`; `BrowseError.kind` is `notConfigured` | `stale` | `notFound` | `failed`):
  - Local: `local_artists`, `local_albums{order: "name"|"artist"}`, `local_artist{id}` → `{artist, albums}`, `local_artist_tracks{id}` (every album A–Z, each in album order: what `s` plays), `local_album{id}` → `{album, tracks}`, `local_folder{path}` → `{path, dirs, tracks}` (one level), `local_folder_tracks{path}` (everything below), `local_playlists`, `local_playlist{id}` → `{playlist, tracks, missing, truncated, hidden, warning}`, `local_search{query}` → `{artists, albums, tracks, totalTracks}` (tracks: `library::search`, at most 1,000; artists/albums: `TagIndex::search`, at most 50 each). Scan state is in the snapshot (`scan`), not a command.
  - Navidrome: `navidrome_artists`, `navidrome_artist{id}` → albums, `navidrome_artist_tracks{id}` (albums fetched in parallel within the fetch limit), `navidrome_album{id}`, `navidrome_albums{sort, offset}` → `{albums, nextOffset}` (pages of 100, the six `AlbumSort`s, stops at `MAX_ALBUMS`), `navidrome_playlists`, `navidrome_playlist{id}` (with `hidden`: Coda's `Hidden` as `{kind: none|some{count}|suspect}`, and `truncated`), `navidrome_random_songs` (Navidrome "Shuffle all": the UI plays them with `playTracks`), `navidrome_search{query}` (`search3`, 20/20/50).
  - Covers for albums, artists and playlists go through the same registry (`CoverService::url_for_key`): local = the first track's art, Navidrome = the item's `coverArt`.
- **Local ids**: `"<generation>:<n>"` for tracks, artists, albums and playlists (indices into the library, valid while it only grows). An id from another generation is `stale` (commands) or skipped with the notice "The library changed; N tracks skipped. Reload the view" (intents); a malformed or out-of-range id is `notFound` / "not in the library". Folders are named by their path of folder names from the root.
- **Queue keys**: `QueueEntryId`'s `Display` (`q12`): stable for the entry's life in this run (React key, intent target), not across restarts.
- **`TrackDto`** also carries `albumId` / `artistId` (local ids, or Navidrome's) for "Go to album/artist"; `null` when unknown. Queue DTOs resolve a local track's id by path when the queue is sent, so a track restored before the scan found it has `id: null` until the queue changes.
- **`TrackRef`**: the shape of a `TrackDto` minus `coverUrl` (`{ source, title?, artist?, … durationMs?, albumId?, artistId? }`, extra fields ignored), so the UI hands back the tracks a browse call gave it. `source` is `{kind:"local", id}` or `{kind:"navidrome", songId, coverArt}`. Local refs are looked up in the scanned `Library` by id and generation, so non-UTF-8 paths play (metadata comes from the scan; unknown or stale ids are skipped with a notice). Navidrome refs are rebuilt with `Track::navidrome` from the given metadata (cleaned and capped like server data; `albumId`/`artistId` kept, bounded), since the backend keeps no browse cache.
- Notices: `{id, text}`; the backend drops them after 5 s (max 4), `dismissNotice` drops one early.

## Covers
- DTOs carry `coverUrl` = `coda://localhost/cover/<16 hex>` (`http://coda.localhost/...` on Windows/Android); the UI appends `/small` (256 px) or `/large` (1024 px).
- The token is a per-run keyed hash of the `CoverKey`; the registry (≤25,000 tokens, oldest dropped) is filled when DTOs are built, so the webview can only fetch covers of tracks it was shown and never names a path. Unknown tokens → 404.
- Local: embedded art, else a folder image. Navidrome: `getCoverArt` via the current client, cached in Coda's disk cache (shared with the TUI). Served as JPEG with `Cache-Control: private, max-age=86400`. `[ui] cover_art = false` turns URLs off.

## Lifecycle
- `tauri-plugin-window-state` remembers the window's size and position.
- Window close / Cmd+Q / last window closed / media-controls Quit → `RunEvent::ExitRequested`: prevent the exit, `begin_quit` (wait ≤3 s for a running settings save (`SettingsLock`), run `EngineHandle::shutdown`, then `app.exit(0)`).
- SIGTERM, SIGINT and SIGHUP (`watch_signals` in `lib.rs`) take the same `begin_quit` path (so they also wait for a settings save); a second signal while quitting terminates mpv and exits at once.
- `RunEvent::Exit` without a finished shutdown (a quit path that skipped `ExitRequested`): blocking, bounded (8 s) shutdown on the event-loop thread.
- A startup still running at exit gets 3 s, then is aborted *and awaited*, which drops a finished-but-unclaimed `PlaybackHandle` before the reply.
- `coda-core`: dropping a `PlaybackHandle` without `shutdown` while its backend runs sends mpv SIGTERM synchronously; on Linux mpv is spawned with `PR_SET_PDEATHSIG = SIGTERM` (covers SIGKILL and aborts); mpv is also spawned with `kill_on_drop`.
- Panics: the app records mpv's pid (`bootstrap::MPV_PID`); a panic hook terminates it when the panic ends the process (always under the release profile's `panic = "abort"`, or on the main thread).
- Session saves that fail are retried with back-off (2 s doubling to 60 s), not only at exit.

## Security
- Capabilities (`capabilities/default.json`): exactly `allow-intent`, `allow-snapshot`, `allow-settings-get`, `allow-settings-test-server`, `allow-settings-save-server`, `allow-settings-disconnect`, `allow-settings-pick-folder`, `allow-settings-set-music-dir`, `allow-settings-set-options`, `allow-onboarding-finish`, and the 19 read-only browse commands `allow-local-*` / `allow-navidrome-*` (our commands, declared via `AppManifest::commands` in `build.rs`, so none is allowed implicitly), `core:event:allow-listen`, `core:event:allow-unlisten`. No emit (the webview cannot forge engine events), menu, tray, path, window or webview APIs. The opener plugin was removed. The dialog and window-state plugins are used from Rust only, so they need no permissions.
- CSP: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' coda: http://coda.localhost data:; connect-src ipc: http://ipc.localhost; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` (`devCsp` adds the Vite HMR socket). `freezePrototype` on.
- DTOs carry no passwords, tokens or stream URLs (a test asserts the snapshot JSON of a Navidrome track has none). Server/tag text is rendered as React text only.

## Frontend (`src/`)
- `lib/types.ts` (DTO mirror, browse block), `lib/ipc.ts` (`intent()`, `fetchSnapshot()`, `onSnapshot/onProgress/onVisualizer`, `coverSrc`, `settingsApi`, `errorText`), `lib/format.ts`, `lib/visualizer.ts` (port of `coda_core::visualizer`: `Meter` smoothing with attack 0.7, decay 1.6/s, 300 ms stale fade; `spreadBands` monotone cubic on a log-frequency axis).
- `state/nav.ts`: the navigation back stack (`Route`s; each entry keeps its scroll position). The sidebar sets a new root; views push; Back pops.
- `lib/browse.ts` (typed browse commands; Navidrome answers cached in memory for 5 min so Back is instant, never the random ones; Retry and a server change clear it), `lib/play.ts` (`playTracks`/`enqueue`/`shuffleAll`, `sameTrack` for the playing row, Go to album/artist, the `s` handler a view registers with `useShuffleContext`).
- `state/store.ts`: two `useSyncExternalStore` stores (app snapshot + queue; progress separately so the position does not re-render the queue). `connect()` subscribes first, then fetches the snapshot.
- `components/`: `Sidebar`, `NowPlayingBar` (cover, title/artist, prev/play/next, seek bar, repeat, volume, queue toggle), `Slider` (pointer drag + own keys), `QueuePanel` (virtualized 36 px rows; double-click/Enter plays, Delete/hover button/context menu removes), `ContextMenu`, `Banner` (problems), `Toasts` (notices), `Cover` (+ generated placeholder), `icons.tsx`.
- `views/`: `NowPlayingView` (`f`, a click on the bar's cover; Esc/`f`/Close or a sidebar entry closes it): large cover over a blurred, darkened small cover, title, artist — album, the shared `SeekBar`, transport, `Visualizer` and Up next; it sends `setVisualizerVisible(true)` while shown and `document.visibilityState` is `visible` (false when minimised/hidden or closed); `SettingsView` (folder, server form via `ServerFields` with Test/Save/Cancel, two-click Disconnect, switches); `Onboarding` (shown instead of the shell while the snapshot has a `noConfig` problem).
- `components/` (M2): `TrackTable` (virtualized 36 px rows inside the view's scroller, disc headers, playing row equaliser, ↑/↓/Enter/double-click, context menu and "…" button), `TrackMenu` (Play, Play next, Add to queue, Go to album, Go to artist; a marked `ADD TO PLAYLIST` spot), `AlbumGrid` (virtualized ~180 px tiles, arrow-key focus, album menu, `onEnd` for infinite scroll), `LoadState` (skeletons, empty, error with Retry / Go back).
- `views/`: `BrowseView` (the stack's top), `ArtistsView` (virtualized list + letter index), `AlbumsView` (local orders; Navidrome sorts with infinite scroll), `ArtistView`, `AlbumView`, `PlaylistsView`/`PlaylistView` (warnings), `FolderView` (breadcrumbs), `SearchView` (debounced 250 ms, grouped per source), `common.tsx` (header with back button, Play/Shuffle, scan line); Settings is a route (`SettingsView`). Local views reload quietly at most every 2 s while the scan grows the library (`useLibraryVersion`). The sidebar hides a source that is not configured.
- `App.tsx`: the shell switches between Onboarding (a `noConfig` problem), Now Playing (an overlay over the browse stack: Back/Escape close it, any navigation closes it) and `BrowseView`. It keeps the stack's root on a configured source and resets it when a browse generation changes. Play actions follow `ready` (started and playback available); queue edits (Play next, Add to queue) follow `started`.
- `components/Visualizer.tsx`: canvas + `requestAnimationFrame`, 32–48 bars by width, redraws only when something moved; reduced motion → 4 updates/s. Colour `--viz-color`.
- `styles/experience.css`: buttons/fields, settings, onboarding, Now Playing.
- `hooks/useShortcuts.ts`: Space, n/p, Ctrl+→/←, ←/→ (∓5 s), +/=/-, r, q, f; ignored while typing in a text field. Controls and shortcuts that send intents are disabled until the engine is `ready` (and transport ones while playback is unavailable). `hooks/useBrowseKeys.ts`: Back (Backspace, Alt+←, Escape, mouse button 3; closes Now Playing first), `/` and Ctrl+F (search), `s` (shuffle the shown context). `hooks/useLoad.ts`, `hooks/useLayout.ts` (element size, scroll restore, library version).
- `styles/`: `tokens.css` (dark first, light via `prefers-color-scheme`, reduced motion), `base.css` (native feel), `app.css` (shell), `browse.css` (browse views).
