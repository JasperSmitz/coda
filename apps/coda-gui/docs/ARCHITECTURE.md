# Coda App — Architecture

What exists in the code (M1 foundation, M2 browse, M3 queue and playlists, the M4 experience slice, 2026-11-05, colour themes, 2026-11-06, and feedback round 1 slice B: one source at a time, play history and Home). Proposals are marked as such.

```text
React UI ──invoke("intent", {intent})──▶ commands.rs ──mpsc(256)──▶ engine.rs (one Tokio task)
   ▲  invoke("snapshot")                                             │ Engine: Player + resolve::dispatch,
   │                                                                 │   Library + scan state, scrobble listen,
   └── events: snapshot / progress / visualizer ◀── Sink (lib.rs) ◀──┤   notices, save revision, emission
React UI ──invoke("local_*" / "navidrome_*")──▶ browse/commands.rs ──▶ BrowseHandle (shared, read-only for commands):
                                                  Library (RwLock, engine writes) + current Client, each with a generation
                                                                     │ Io: PlaybackHandle (mpv), scan rx, ping,
webview <img src="coda://localhost/cover/<token>/small">             │   Scrobbler, Saver (blocking writes), 50 ms tick
   └──▶ cover.rs (URI scheme) ──▶ coda_core::cover::load + disk cache
```

## Crates
- `coda-core` (`crates/coda-core` at the repository root, lib `coda_core`): Coda's shared engine, also used by the terminal player (`crates/coda-tui`). Additions for the GUI in M1: `cover::load` (async, one cover at a key and size; `spawn_load` now uses it), `cover::encode_jpeg`, `Library::track_id_by_path`, `logging::init_logging_at(path)`, `Drop for PlaybackHandle` (SIGTERM to a still-running mpv), and on Linux `PR_SET_PDEATHSIG` in `mpv_command`. In M4: `config_writer::{Preferences, write_preferences, read_preferences}` (music folder, `scrobble`, `[ui] cover_art`; `[navidrome]` kept as is, same backup/atomic-write rules), `playback::mpv::process::{find_program, default_program, FALLBACK_DIRS}` (`spawn_backend` looks for mpv on `PATH`, then `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`), and `Player::set_volume` now works while stopped (the request becomes the shown and saved preferred volume; mpv accepts volume while idle). In M2: `Track::album_id`/`artist_id` (Navidrome ids for navigation, set from `albumId`/`artistId`; not saved in the session), `cover_art` on Navidrome `Artist`/`Album`/`Playlist` and `artist_id` on `Album`, `TagIndex::album_of`/`artist_of` (a local track's album/artist) and `TagIndex::search` (artists/albums by name).
- `coda-core` (M3): `Queue::move_entries(ids, to)` / `Player::move_entries` (a set of entries, in queue order, moved as one block to a drop gap: before the entry now at `to`, `len` = the end; `current` and the "play next" anchor kept; no revision bump when the order stays).
- `src-tauri` (`coda-app`, lib `coda_app_lib`): the backend.

## Backend modules (`src-tauri/src/`)
- `lib.rs`: Tauri builder; registers the `coda` URI scheme, creates the main window in `setup` (`"create": false` in `tauri.conf.json`, built with `WebviewWindowBuilder::from_config` plus the theme's initialization script and its background as the native window background: the dark one, switched to the light one at once when the window is light; `Appearance` is managed before the window exists), spawns the engine in `setup`, manages `EngineHandle`, and owns the quit sequence.
- `bootstrap.rs`: `Paths` (GUI files under `<Coda state dir>/coda-app/`: `session.json`, `history.json` (play history, loaded at startup with `history::load` on a blocking thread, alongside the session restore), `coda-app.log`, `media/` for the media-controls cover; Coda's cover cache is shared; `tui_session` = the TUI's `state.json`), `init_logging`, and `start()`: `Config::load(cli_from_process(), Env::from_process())` (`CODA_MUSIC_DIR` honoured like the TUI), password + `navidrome::Client` (`config::navidrome_client`), `playback::spawn_backend()` and the session restore, run concurrently. Restore first imports the TUI's session once when the GUI has none: `session::read_valid` (coda-core; non-blocking open, regular files only, 16 MiB cap, decoded, never renames) and only a valid one is copied (`create_new`, `O_NOFOLLOW`, 0600, renamed into place); a `coda-app/.tui-imported` marker records the attempt (valid or not), so it never happens again, even after the GUI's own session is set aside. The TUI's file is never modified. Every failure becomes a `ProblemDto` (`noConfig`, `config`, `mpvMissing`, `playback`, `navidrome`); nothing panics.
- `engine.rs`: the actor.
  - `Engine` is the synchronous core: `start(sources, playback_problem, restored)`, `handle_intent`, `handle_playback_event`, `handle_scan_event`/`scan_closed`, `handle_ping`, `handle_scrobble_failure`, `tick`; outputs `Vec<PlaybackCommand>` plus queued visualizer frames and scrobble requests. Every player call goes through `resolve::dispatch` (which also re-announces the gapless next after queue edits), then `take_messages()` become notices and the save revision is checked.
  - `run` is the loop: `select!` over startup completion, intents, playback events, scan events, the Navidrome ping, the first scrobble failure, and a 50 ms tick (notice expiry, session-save polling). After each branch it flushes: visualizer frames at once, scrobbles to the worker, a `snapshot` event if anything visible changed, `progress` if the position changed and ≥100 ms passed.
  - Startup runs as its own task, so the UI gets a `starting` snapshot immediately (a password command or keychain prompt can take a while). Intents other than visualizer visibility and notice dismissal are ignored until `ready`.
  - Session: revision based (`Player::revision`), saved 2 s after the last change, one blocking write at a time; restore never auto-plays; final save at exit bounded to 2 s. The GUI has its own session file, so it never overwrites the TUI's queue.
  - Scrobbling: the engine owns a `coda_core::navidrome::scrobble::Scrobbling` (the listen policy shared with the TUI): `started`/`progressed` after the player handles `Started`/`Position`, `player_changed` in `dispatch`, requests handed to the `Scrobbler` by the loop. The engine keeps only the notice text and the `scrobble` setting.
  - Visualizer: `SetVisualizer(true)` only while the UI says a view is visible (`setVisualizerVisible`), never after `VisualizerUnavailable`; frames are forwarded raw only for `audible_load` while playing. Smoothing/decay is the UI's job (none yet: no visualizer view in M1).
  - Live settings (`engine/settings.rs`, `Msg::Settings` → `Engine::apply_settings`, refused until `ready`): `Client` (port of the TUI's `swap_client`: new `CoverService` client, which forgets remote cover tokens and mixes a new generation into new ones so the webview never shows the old server's cached art; queue resent; `Scrobbling::client_replaced` (listen and waiting requests dropped, the current load never reported, the first failure shown again); `Player::client_changed` re-announces/reloads remote entries signed by the old client; the loop pings the new client and replaces the scrobbler), `MusicDir` (new `Library`, `Scanning`, the loop starts a new scan; dropping the old receiver ends the old scan), `CoverArt` (URLs on/off, queue resent), `Scrobble` (needs a client; `Scrobbling::switch`: a track already playing is not reported halfway). `Client`/`MusicDir` clear `noConfig`/`config` problems (onboarding).
  - `Client` and `MusicDir` also update the `BrowseHandle` (new client / new library, each a new generation; the queue is resent so local ids follow the new library).
  - Shutdown (`EngineHandle::shutdown`): `phase = shuttingDown` snapshot, wait ≤3 s for a still-running startup (else abort and await it, so a `PlaybackHandle` it holds is dropped and mpv terminated), final save, `PlaybackHandle::shutdown(2 s)`, reply.
  - Queue edits (M3, `engine/queue_edit.rs`): `moveEntries` (gap resolved from the `before` key), `removeEntries` (the playing entry removed last, so playback moves on to an entry that stays), `playNextEntries` (moved right after the current entry), `shuffleUpcoming` (`Player::shuffle_upcoming`, Coda's notice). Each goes through `Player` and then `dispatch`, which re-announces the gapless next.
  - `engine/playlists.rs`: `Msg::Playlist` for the playlist editor: `EngineHandle::notify(text)` (an edit's outcome as a notice) and `EngineHandle::queue_songs()` (the queue's Navidrome song ids in order + the number of local tracks, Coda's `save_queue_as_playlist`).
  - Play history (`engine/history.rs`, owner feedback round 1): the engine owns a `history::History`. `playTracks` carries an optional `context` (`PlayContextDto`: `album`/`artist`/`playlist` `{source, id, name?, subtitle?, coverUrl?}` or `folder {path}`); when the play replaced the queue, the context is resolved (a local id of the current generation → a stable key; a stale or unknown id records nothing; a Navidrome cover URL → its `coverArt` id through `CoverService::key_for_url`, so no token is stored) and recorded as a context play, and the queue's entries are remembered as played from it. `playLocal` records its folder or artist itself; `shuffleLibrary` and context-less plays (search results) end the remembered context. Listens: on `Started` of the current load a second `Listen` (coda-core's scrobble rule: half the track or 4 minutes, ≥30 s tracks; every source, independent of scrobbling) counts for the track's album (Navidrome `albumId`; local `TagIndex::album_of` → stable key) and, if the entry came from the remembered context, that context (once per key). Saved like the session: 2 s after the first unsaved change (`HistorySaver`, one blocking write at a time, back-off on failure up to 60 s), and once more at quit, alongside the final session save (same 2 s bound). Navidrome history is per server: the engine keeps the current client's `history::server_id` (set at start and on every client swap) and stamps it on each Navidrome context it records; Home rows and Daily Picks are read for that server only (none while disconnected), so another server never shows the old one's, and switching back shows it again. Navidrome entries already in the queue at a client swap are remembered (`other_server_entries`) and their album listens are not counted for the new server. Fetched picks carry the `server_id` of the client they were fetched with (`SetDaily`), and the engine refuses them (the command answers `stale`) when that is no longer the current server. Every history change marks the snapshot dirty; `Snapshot.historyRevision` tells Home to reload its rows.
  - `Msg::History` (`HistoryMsg`): the Home commands ask for a source's rows (`home_rows`), the cached Navidrome picks of a date, or store them (the first picks of a day stay).
- `history.rs` (+ `history/`): the history model and file. `Context {source, server, kind, id, name, subtitle, coverArt}`; `server` (Navidrome only, required) is `server_id`: FNV-1a 64-bit hex of the base URL and user name (stable across runs; the file never holds the URL or user name in plain text, though a known server's id can be confirmed by hashing; the client normalises the trailing slash); `Scope` (`Local` | `Navidrome(server)`) selects what a Home view reads; local ids are stable keys: album `"<artist>\u{1f}<album>"` (trimmed, lowercased tag names as `TagIndex` groups them), artist name, playlist name, folder path joined by `/` (`/` = the root). Bounds: last 500 context plays, counts for ≤5,000 contexts (least recently heard dropped), 12 picks; text cleaned (control characters, ≤256 chars), ids ≤4,096 chars. `history.json` (`{version: 1, plays, counts, dailies}`; Navidrome entries without a valid server id are dropped on load): read with `theme::fsio::read_regular` (regular files only, never blocking on a FIFO, ≤16 MiB); invalid JSON, an older unknown version or a non-regular file is renamed to `history.json.bad.<unix-seconds>` and the history starts empty; an unreadable file (I/O error), a newer version or a file over 16 MiB is kept and disables saving for the run so it is never overwritten; `save` never writes more than 16 MiB (it leaves out the least recently heard half of the counts and the oldest half of the plays until it fits); writes are atomic (`fsio::write_atomic`, 0600). No URLs, tokens or credentials. Home resolution (`home_dto`): local contexts are looked up in the current library by key (gone → skipped) and get current ids, names and first-track covers; Navidrome contexts show what was stored, their cover through the registry. Daily Picks: local = the 12 albums whose key ranks lowest under FNV-1a of `date + key` (each album's rank depends only on the date and its key: same all day, across restarts and scan orders, and a library edit changes the picks only where an added album outranks one or a picked one goes away); Navidrome = `getAlbumList2 type=random size=12` at the first ask of the day, cached in the file with the date and server (the latest picks of at most 4 servers).
  - `history/commands.rs`: `home_history{source}` → `{recent, mostPlayed}` (`HomeItem`s, ≤20 each; Navidrome most played = playlists only, its albums come from the server's `frequent` list in the UI), `home_daily_picks{source, date}` (`YYYY-MM-DD`, the UI's local day; else `notFound`) → `Album[]`. Errors are `BrowseError`s.
- `playlists.rs` (+ `playlists/`, M3): Navidrome playlist edits through `coda_core::navidrome::edit::run` (create, save queue, add, rename, delete, remove, reorder; removals and reorders are a replace after a refetch that must match the shown list, as in Coda).
  - `PlaylistEditor` (managed state) holds a `tokio::sync::Mutex` for an edit's whole run, so edits run one at a time in order (Coda's `EditRunner`); `begin_quit` waits for a running one ≤3 s (`EDIT_GRACE`) before the engine shutdown. Edits run in the command's task, never on the engine task.
  - Each edit takes the browse handle's client only once it holds the lock, so an edit queued behind another never writes to a server the user has since left (no client then: `refused`). If the client generation changed while it ran, the outcome keeps its status (the old server may have applied it) and the message ends with "(made with the previous server connection)".
  - `finish` (quit) sets a closing flag first: edits still queued are refused ("Not changed: Coda is quitting"), the running one gets ≤3 s.
  - Validation before anything is sent (`refused`): names trimmed, control characters replaced, 1–256 characters; ids non-empty, ≤256 characters, no control characters, at most `MAX_PLAYLIST_ENTRIES`; remove indices in range, no more of them than songs, and never all (`LAST_SONG`); a reorder must be a permutation (the shown order is a no-op). One removed index is an `EditOp::Remove`, several a `Replace`.
  - Hidden entries: the UI sends the `hidden` it confirmed (`HiddenDto`, `none` without a dialog); it becomes the edit's bound (`Hidden::bound`), so a server with more hidden entries than confirmed answers `stale` and nothing is written.
  - Messages follow Coda's `edit_message` (GUI wording); every outcome is returned and shown as a notice. Errors are logged with `Error::detail()` only.
- `browse.rs` (+ `browse/`): everything the browse views read.
  - `BrowseHandle` (managed Tauri state, cheap `Clone`): the local `Library` behind a `std::sync::RwLock` plus a *library generation*, and the current Navidrome `Client` plus a *client generation*. The engine is the only writer and **never waits for the lock** (`engine/library.rs`): a library replacement (start, a music-folder change in settings; bumps the library generation), each scan batch/playlist and the scan end are queued as ops and applied with `try_write_local`; while a browse read holds the lock they stay queued and are applied on the next event or the 50 ms tick (a replacement drops ops still queued for the old library). Since no writer ever waits, the engine's own reads (refs, queue DTOs) never wait either. `ScanEvent::Finished` resends the queue so restored local entries get their ids. `set_client` publishes the client at start and on every settings client swap (bumping the client generation). Both generations are in the snapshot (`browse: {library, server}`); the UI clears its Navidrome cache and resets a stack holding that source's views when one changes. Commands never touch `Player` or the engine channel.
  - Local commands run their read on a blocking thread (`BrowseHandle::local`), so long reads (search, a 5,000-album list) never run on the engine task.
  - Navidrome commands go through `BrowseHandle::fetch`: at most `MAX_CONCURRENT_FETCHES` (4, Coda's) requests at once (a semaphore), of which an artist play-all's album fetches take at most `MAX_JOB_FETCHES` (2); a result that arrives after the client generation changed is dropped as `stale`. Failures are logged with `Error::detail()` and returned as their `Display` text (never credentials).
  - `browse::track_dto` builds every `TrackDto` (queue and browse), so local tracks are named the same way everywhere.
  - `browse/dto.rs` (browse DTOs and `BrowseError {kind, message}`), `browse/local.rs` (queries over a `LocalView`), `browse/navidrome.rs` (queries through the client), `browse/commands.rs`, `browse/tests.rs`.
- `lyrics.rs` (+ `lyrics/tests.rs`): `now_playing_lyrics({track})` → `LyricsDto {timed, lines: [{startMs, text}]} | null`, for Now Playing's lyrics mode. It runs on the command's task, never the engine actor: a local id is resolved through the `BrowseHandle` (path looked up under the library lock, the file read by `coda_core::lyrics::read_local` after it, on a blocking thread; a stale generation, an unknown id, no library or no id is `null`); a Navidrome song goes through `BrowseHandle::fetch_raw` (the browse fetch limit and stale-client rule, without `fetch`'s warn log) to `Client::lyrics` with the ref's artist and title (capped). Lyrics with no text are `null`. A failed read or request is logged at debug and rejects with a message (the view shows "Couldn't load lyrics"). Nothing is cached in the backend.
- `dto.rs`: serde DTOs (camelCase), mirrored by hand in `src/lib/types.ts`. `playlists/dto.rs`: `EditOutcomeDto`.
- `commands.rs`: `intent(intent)` and `snapshot()`; the browse commands live in `browse/commands.rs`.
- `settings.rs`: the Settings view's and onboarding's commands (below). Reads the file with `config::read_for_setup` + `config_writer::read_preferences` (never resolves the password); ownership like the TUI's settings: a server Coda wrote (keychain) can be edited/disconnected, one set outside Coda (`CODA_NAVIDROME_*`, hand-written `password`/`password_command`) is shown and left alone; `onboarding::navidrome_blocked_by` blocks saving a server. Saves go through `setup_actions` (ping first, then keychain, then config; old keychain entry removed) and `config_writer::write_preferences`, on blocking threads, one at a time (`SettingsLock`, which the quit sequence awaits ≤3 s before the engine shutdown); only then `EngineHandle::apply_settings`. `ServerInput` (the typed password) has a redacted `Debug`; no DTO carries a password. The folder picker is `tauri-plugin-dialog` used from Rust (no JS plugin API, no capability).
- `media.rs`: OS media controls (`souvlaki`, zbus MPRIS backend on Linux, `MPNowPlayingInfoCenter` on macOS). `TauriSink` feeds it every snapshot/progress; `Publisher` (pure, tested) publishes metadata on a track change, status on a change, the position on the first report, a jump >1.5 s or every 5 s while playing. Covers: loaded through `CoverService::image_for_url`, written as `<state>/coda-app/media/cover-<n>.jpg` (0600, older ones removed) and published as `file://`. Events → intents (`Play`/`Pause` only toggle when needed, seek ±10 s, set position, volume; `Raise` focuses the window; `Quit` takes the normal quit path). Every souvlaki call runs on the main thread (`run_on_main_thread`, controls in a main-thread `thread_local`); a failure to create them is logged and the app runs without. Dropped at `RunEvent::Exit`.
- `cover.rs`: `CoverService` (registry, current client, small/large disk caches, 4 concurrent loads) and the protocol handler.
- `theme/` (colour themes; DESIGN.md "Theming"; independent of the engine, the webview's look only):
  - `parse.rs`: Ghostty theme files (`key = value`, `#` comments; `palette = N=#rrggbb`, `background`, `foreground`, `cursor-*`, `selection-*`), plus Coda's keys `coda-accent = #rrggbb | palette:N` and `coda-<token> = #rrggbb[aa]` for every overridable token (`coda-surface` = `coda-surface-1`), and `coda-explicit = key, …` (the colours the user chose; written by the editor). Untrusted input: ≤64 KiB, hex only, a malformed value for a used key rejects the file, unknown keys are ignored. `write` produces a Ghostty file back (Ghostty keys first, then `coda-*`).
  - `fsio.rs`: `read_regular` (the path's type is checked first, following symlinks; then opened with `O_NONBLOCK` and checked again on the handle; size-capped), so a FIFO or device in a theme folder or as Ghostty's config can never hang startup or the list. `write_atomic` (temp file, sync, rename, sync the folder); `write_target` resolves a symlinked `settings.toml` so the link stays a link (a symlink in the custom themes folder is replaced, never its target).
  - `sources.rs`: built-ins (`themes/*`, compiled in with `include_str!`; origins in `themes/THEMES-CREDITS.md`), Ghostty's installed themes (macOS `/Applications/Ghostty.app/Contents/Resources/ghostty/themes`, Linux `/usr/share/ghostty/themes`, `$GHOSTTY_RESOURCES_DIR/themes`), `<config>/ghostty/themes`, then `<config>/coda-app/themes` (custom; `<config>` = `$XDG_CONFIG_HOME` if absolute, else `~/.config`, on macOS too). Merged by name, later wins; each entry has a `Source` (`builtIn`/`ghostty`/`custom`). ≤2,000 files per folder; names are file names (no `/`, `\`, leading dot or control characters, ≤100 characters); invalid files are skipped with an info log. `find` looks up one name without reading every folder (startup).
  - `derive.rs`: the theme → tokens. Base: `bg`, `fg`, `accent` (`coda-accent`, else palette 3, else 4/5 when 3 fails 3:1), `danger` (palette 1), `selection`, `palette-0..15` (missing entries from Coda's palette). Derived (OKLab mixes, the maths of `color-mix(in oklab)`): `surface-1..3`, `border`, `text`, `text-2/3`, `accent-text`/`danger-text` (black or white), `accent-soft`/`danger-soft`, `success` (palette 2), `hover`, `selected`, `selection-text`, shadows, `backdrop`, the Now Playing `np-bg`/`np-text`/`np-scrim` (kept dark: white reads at 12:1 on `np-bg`), `on-cover*`, `cover-1..6` (palette 1–6 darkened until white initials read at 3:1), `viz`. Scheme: light when the background's OKLab L > 0.6. Contrast guard (WCAG ratios, OKLCH lightness nudged toward whichever of black/white reads better; falls back to the extreme): text ≥4.5 on bg and surfaces 1–3, text-2 ≥4.5, text-3/accent/danger/success ≥3, selection text ≥4.5, Now Playing text ≥4.5. A colour the user set (a theme file's `coda-explicit` keys, a saved accent, an editor edit; a reset un-sets) is never adjusted; failing checks come back as `contrast` warnings on the token. Saved and duplicated copies carry the same `coda-explicit` set, so they look exactly like the original.
  - `ghostty.rs`: the `theme` line of Ghostty's config (`<config>/ghostty/config`, then macOS `~/Library/Application Support/com.mitchellh.ghostty/config`; last wins; ≤1 MiB each): `Name`, `"Name"`, an absolute path (that file is read, named by its file name; a relative path is looked up by its file name), `light:A,dark:B` in either order. `config-file = [?]path` includes are followed after the including file, relative to it (≤4 levels, ≤16 files).
  - `prefs.rs`: the GUI's own `<config>/coda-app/settings.toml` (not Coda's `config.toml`): `mode` (`single` | `system` | `ghostty`, default `system`), `theme`, `lightTheme`, `darkTheme` (defaults Coda / Coda Light), `[accents]` (theme → `#rrggbb`), `visualizer` (`accent` | `palette`), `source` (`local` | `navidrome`, the browsed source; absent until chosen; `appearance_set` keeps it, only `ui_source_set` changes it). Sanitized on load (bad names → defaults, non-hex accents dropped); an invalid file means the defaults and is renamed to `settings.toml.bad` on the next save; writes are atomic (temp file + rename).
  - `mod.rs`: `Appearance` (managed state: folders, prefs path, Ghostty config paths, and the prefs behind a `tokio::sync::Mutex` that also serializes custom theme file changes), `resolve` (a theme + saved accent + editor edits → `ResolvedTheme {name, source, scheme, tokens}`), `applied` (the light and dark themes the mode selects; a missing theme falls back to the built-in default with a note), `init_script`, and the custom theme operations (`save_custom`, `rename_custom`, `duplicate`, `delete_custom`: only files in the custom folder are written or removed; a new name may not be taken by any theme).
  - `commands.rs`: the Tauri commands below; file work on blocking threads.

## IPC contract
- Commands: `intent({ intent })`, `snapshot()` → full `Snapshot` (queue included). Settings (each rejects with a message to show): `settings_get()` → `Settings` (`configPath`, `musicDir` as written, `musicDirEnv`, `server` = `notConfigured` | `coda{url, username}` | `outside{url, username, by}`, `serverBlockedBy`, `scrobble`, `coverArt`, `problem`), `settings_test_server({server})`, `settings_save_server({server})`, `settings_disconnect()`, `settings_pick_folder()` → path or `null`, `settings_set_music_dir({folder})` (refused while `CODA_MUSIC_DIR` is set), `settings_set_options({coverArt?, scrobble?})`, `onboarding_finish({musicDir?, server?})`. `server` is `{url, username, password}`.
- Events:
  - `snapshot` (coalesced on the 50 ms tick, only when the snapshot differs from the last one sent). `queue` is `null` when the entry list (by key) did not change, so a 10,000-entry queue is not resent on every status change; the UI keeps its last queue. `browse: {library, server}` carries the browse generations. A `snapshot()` call resets this, so the next event carries the queue again (the UI applies the command's result only if no event arrived first).
  - `progress`: `{ positionMs, durationMs }` of the heard track, ≤10/s.
  - `visualizer`: `{ levels: [l, r], bands: [7 × number|null] }`, ≤30/s, only while enabled.
- `Intent` (tagged by `type`): `togglePause`, `next`, `previous`, `seekTo{seconds}`, `seekBy{seconds}`, `setVolume{volume}`, `cycleRepeat` (no notice: the repeat button shows the mode), `playEntry{key}`, `removeEntry{key}`, `clearQueue`, `setVisualizerVisible{visible}`, `playTracks{tracks, start?, shuffle?}`, `enqueue{tracks, next?}`, `dismissNotice{id}`, `shuffleLibrary` (local "Shuffle all": every scanned track shuffled, a random sample at `MAX_QUEUE_LEN`, as in Coda), `playTracks` also takes `context?` (the play history, above), `playLocal{context: {kind:"folder", path} | {kind:"artist", id}, start?, shuffle?}` (`engine/context.rs`: the engine resolves the context's track ids under its non-waiting read and clones only what the queue takes: shuffled = the start first plus a random sample, else `context_window` around the start; stale ids → notice). M3: `moveEntries{keys, before}` (one block in queue order to the gap before the entry `before`, `null` = the end; named by key, not index, so a queue that changed since the UI drew it still gets the block where it was dropped; an unknown `before` moves nothing), `removeEntries{keys}`, `playNextEntries{keys}`, `shuffleUpcoming`. Unknown keys are ignored.
- Playlist edit commands (M3, Navidrome; each resolves with `EditOutcome {status: done|partial|stale|failed|refused, message, created}`, the message also a notice): `playlist_create{name, songs}`, `playlist_save_queue{name}`, `playlist_add{playlistId, name, songs}`, `playlist_rename{playlistId, oldName, name}`, `playlist_delete{playlistId, name}`, `playlist_remove{playlistId, name, expected, indices, hidden}`, `playlist_reorder{playlistId, name, expected, order, hidden}`. `name`/`oldName` of an existing playlist are for messages only; `expected` is the song ids as shown, `songs` Navidrome song ids.
- `Playlist` DTOs carry `editable` (`Access::editable_by` the client's user; always `false` for local) and `readOnlyReason` (Coda's `read_only_reason`).
- Browse commands (all async, `Result<DTO, BrowseError>`; `BrowseError.kind` is `notConfigured` | `stale` | `notFound` | `failed`):
  - Local: `local_artists`, `local_albums{order: "name"|"artist"}`, `local_artist{id}` → `{artist, albums}`, `local_album{id}` → `{album, tracks}`, `local_folder{path}` → `{path, dirs, tracks}` (one level), `local_playlists`, `local_playlist{id}` → `{playlist, tracks, missing, truncated, hidden, warning}`, `local_search{query}` → `{artists, albums, tracks, totalTracks}` (tracks: `library::search`, at most 1,000; artists/albums: `TagIndex::search`, at most 50 each). Playing a whole folder or local artist is the `playLocal` intent (below), so those lists never cross IPC. Ids and queries from the UI are bounded (256 chars; a Navidrome id longer or empty is `notFound`, a query is trimmed and cut). Scan state is in the snapshot (`scan`), not a command.
  - Navidrome: `navidrome_artists`, `navidrome_artist{id}` → albums, `navidrome_artist_tracks{id}` (albums fetched in parallel within the fetch limit), `navidrome_album{id}` (header from `getAlbum` itself via `Client::album_detail`: name, album artist and *their* id, year, cover; a song's `artistId` is the track artist's and never used for the header), `navidrome_albums{sort, offset}` → `{albums, nextOffset}` (pages of 100, the six `AlbumSort`s, stops at `MAX_ALBUMS`), `navidrome_playlists`, `navidrome_playlist{id}` (with `hidden`: Coda's `Hidden` as `{kind: none|some{count}|suspect}`, and `truncated`), `navidrome_random_songs` (Navidrome "Shuffle all": the UI plays them with `playTracks`), `navidrome_search{query}` (`search3`, 20/20/50).
  - Covers for albums, artists and playlists go through the same registry (`CoverService::url_for_key`): local = the first track's art, Navidrome = the item's `coverArt`.
- **Local ids**: `"<generation>:<n>"` for tracks, artists, albums and playlists (indices into the library, valid while it only grows). An id from another generation is `stale` (commands) or skipped with the notice "The library changed; N tracks skipped. Reload the view" (intents); a malformed or out-of-range id is `notFound` / "not in the library". Folders are named by their path of folder names from the root.
- **Queue keys**: `QueueEntryId`'s `Display` (`q12`): stable for the entry's life in this run (React key, intent target), not across restarts.
- **`TrackDto`** also carries `albumId` / `artistId` (local ids, or Navidrome's) for "Go to album/artist"; `null` when unknown. Queue DTOs resolve a local track's id by path when the queue is sent, so a track restored before the scan found it has `id: null` until the queue changes.
- **`TrackRef`**: the shape of a `TrackDto` minus `coverUrl` (`{ source, title?, artist?, … durationMs?, albumId?, artistId? }`, extra fields ignored), so the UI hands back the tracks a browse call gave it. `source` is `{kind:"local", id}` or `{kind:"navidrome", songId, coverArt}`. Local refs are looked up in the scanned `Library` by id and generation, so non-UTF-8 paths play (metadata comes from the scan; unknown or stale ids are skipped with a notice). Navidrome refs are rebuilt with `Track::navidrome` from the given metadata (cleaned and capped like server data; `albumId`/`artistId` kept, bounded), since the backend keeps no browse cache.
- Appearance commands (each rejects with a message to show): `appearance_get()` → `Appearance {prefs, light, dark, ghostty: {light, dark}|null, notes, themesFolder}` (`light`/`dark` are `ResolvedTheme`s, equal in single mode; Ghostty's config is read again on each call in Ghostty mode); `appearance_set{prefs}` → `Appearance` (saved first); `theme_list()` → `ThemeSummary[]` (`name`, `source`, `scheme`, `bg`, `fg`, `accent`, `swatches` = palette 1–6); `theme_resolve{name, edits?}` → `ResolvedTheme` (previews; `edits` = `{key: "#hex" | null}`, `null` drops an override); `theme_save_custom{base, name, edits, replacing}` (writes `<name>` in the custom folder, removes `replacing` if renamed, bakes in a saved accent, selects it: the matching slot in system mode, else single mode) → `Appearance`; `theme_rename{from, to}`, `theme_duplicate{name, to}`, `theme_delete{name}` (custom only; references fall back to the defaults unless a theme of that name shows again; renames that change only the letter case work on case-insensitive file systems) → `Appearance`; `theme_window_background{color}` (`#rrggbb`: the native window's background, sent by the UI when the applied background changes); `theme_reveal_folder()` (creates the custom folder and opens it with `open`/`xdg-open`; no path comes from the webview). `ui_source_get()` → `"local" | "navidrome" | null`, `ui_source_set{source}` (saved at once, the file's other keys kept). `ResolvedTheme.tokens`: `{key, value, overridden, contrast: {ratio, min, against}|null}`; `key` is the CSS custom property without `--`.
- Notices: `{id, text}`; the backend drops them after 5 s (max 4), `dismissNotice` drops one early.

## Covers
- DTOs carry `coverUrl` = `coda://localhost/cover/<16 hex>` (`http://coda.localhost/...` on Windows/Android); the UI appends `/small` (256 px) or `/large` (1024 px).
- The token is a per-run keyed hash of the `CoverKey`; the registry (≤25,000 tokens, least recently used dropped: a token handed out again moves to the back, so the playing track, the queue and lists on screen keep their covers while a long list is built) is filled when DTOs are built, so the webview can only fetch covers of tracks it was shown and never names a path. Unknown tokens → 404.
- Local: embedded art, else a folder image. Navidrome: `getCoverArt` via the current client, cached in Coda's disk cache (shared with the TUI). Served as JPEG with `Cache-Control: private, max-age=86400`. `[ui] cover_art = false` turns URLs off.

## Lifecycle
- `tauri-plugin-window-state` remembers the window's size and position.
- Window close / Cmd+Q / last window closed / media-controls Quit → `RunEvent::ExitRequested`: prevent the exit, `begin_quit` (wait ≤3 s for a running settings save (`SettingsLock`), run `EngineHandle::shutdown`, then `app.exit(0)`).
- SIGTERM, SIGINT and SIGHUP (`watch_signals` in `lib.rs`) take the same `begin_quit` path (so they also wait for a settings save); a second signal while quitting terminates mpv and exits at once.
- `RunEvent::Exit` without a finished shutdown (a quit path that skipped `ExitRequested`): blocking, bounded (8 s) shutdown on the event-loop thread.
- A startup still running at exit gets 3 s, then is aborted *and awaited*, which drops a finished-but-unclaimed `PlaybackHandle` before the reply.
- `coda-core`: dropping a `PlaybackHandle` without `shutdown` while its backend runs sends mpv SIGTERM synchronously; on Linux mpv is spawned with `PR_SET_PDEATHSIG = SIGTERM` (covers SIGKILL and aborts); mpv is also spawned with `kill_on_drop`.
- Panics: the app records mpv's pid (`bootstrap::MPV_PID`); a panic hook terminates it when the panic ends the process (always under the `release-gui` profile's `panic = "abort"`, or on the main thread).
- Session saves that fail are retried with back-off (2 s doubling to 60 s), not only at exit.

## Security
- Capabilities (`capabilities/default.json`): exactly `allow-intent`, `allow-snapshot`, `allow-settings-get`, `allow-settings-test-server`, `allow-settings-save-server`, `allow-settings-disconnect`, `allow-settings-pick-folder`, `allow-settings-set-music-dir`, `allow-settings-set-options`, `allow-onboarding-finish`, the 17 read-only browse commands `allow-local-*` / `allow-navidrome-*`, the 7 playlist edits `allow-playlist-{create,save-queue,add,rename,delete,remove,reorder}`, and the 10 appearance commands `allow-appearance-{get,set}`, `allow-theme-{list,resolve,save-custom,rename,duplicate,delete,reveal-folder,window-background}`, `allow-ui-source-{get,set}`, `allow-home-history`, `allow-home-daily-picks`, `allow-now-playing-lyrics` (our commands, declared via `AppManifest::commands` in `build.rs`, so none is allowed implicitly), `core:event:allow-listen`, `core:event:allow-unlisten`. No emit (the webview cannot forge engine events), menu, tray, path, window or webview APIs. The opener plugin was removed. The dialog and window-state plugins are used from Rust only, so they need no permissions.
- CSP: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' coda: http://coda.localhost data:; connect-src ipc: http://ipc.localhost; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` (`devCsp` adds the Vite HMR socket). `freezePrototype` on.
- The theme reaches the webview as an initialization script (`theme::init_script`, injected natively before the document, so the CSP does not apply to it): JSON of token names and hex values only, never theme names or paths. It sets them as inline custom properties on `<html>` (a `MutationObserver` waits for `<html>` if needed). Theme files and Ghostty's config are untrusted input (above); theme names are shown as React text.
- DTOs carry no passwords, tokens or stream URLs (a test asserts the snapshot JSON of a Navidrome track has none). Server/tag text is rendered as React text only.

## Platform, packaging, CI
- Linux is built and tested in Docker: `docker/linux-dev.Dockerfile` (Debian trixie, native arch; Rust stable, Node 22 + pnpm 12.8.1, the webkit2gtk-4.1/GTK dev packages, mpv, PulseAudio) and `scripts/linux-check.sh` (pnpm build, fmt, clippy, tests, ignored mpv tests against a PulseAudio null sink, `tauri build --debug --no-bundle`; `--bundle` adds deb/AppImage/rpm; `--shell`). Linux target dir, cargo registry, pnpm store and `node_modules` are named volumes, never the host's.
- The engine's MSRV (`coda-core` `rust-version = 1.89`) makes Cargo's resolver hold `tauri` at 2.11.x (2.12 needs 1.90), so `@tauri-apps/api` is pinned to `~2.11` to match (`tauri build` refuses mismatched minors). Raise both together.
- `tauri.conf.json` `bundle`: targets deb, appimage, rpm (Linux) and app, dmg (macOS); category Music; deb/rpm depend on `mpv`; macOS 11+. Icons are generated from `src-tauri/icons/source/icon.svg` (the coda sign in the accent amber).
- `packaging/arch/PKGBUILD` (package `coda-app`) builds a committed ref of a local checkout with `tauri build --no-bundle` and installs the binary, `packaging/linux/coda-app.desktop`, hicolor icons and the license.
- `.github/workflows/coda-gui-ci.yml` (repository root, `working-directory: apps/coda-gui`): rustfmt; per OS (ubuntu-latest, macos-latest) pnpm build, clippy and tests of `coda-app` and `coda-core`, `tauri build --debug --no-bundle`, plus the ignored mpv tests on Linux. `coda-gui-release.yml` (tags `coda-gui-v*.*.*`): checks the tag against tauri.conf.json, Cargo.toml and package.json, builds bundles with `--profile release-gui` on ubuntu-24.04 (x86_64, arm64) and macos-latest (arm64), creates a draft release (`--latest=false`) with checksums. Actions are pinned by SHA; permissions are read-only except the publish job.
