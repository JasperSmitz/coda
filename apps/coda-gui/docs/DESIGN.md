# Coda App — Design

A calm, cover-first desktop music player. It should feel like a native app, not a web page: no page scroll, no link styling, no hover-underlines, text not selectable except in inputs, the default cursor on controls, right-click context menus where they help.

## Layout

```text
┌────────────┬───────────────────────────────────────┬──────────────┐
│ Sidebar    │ Main view                             │ Queue        │
│[Local|Navi]│                                       │ (toggle, q)  │
│ status     │  header: title, sort, actions         │              │
│ Home       │  ─────────────────────────────        │ Now playing  │
│ Search     │  Home rows / album grid / track table │ Up next ...  │
│ Albums     │  (scrolls on its own)                 │              │
│ Artists    │                                       │              │
│ Playlists  │                                       │              │
│ Mixes      │                                       │              │
│ Folders    │  (Folders: local only)                │              │
│            │                                       │              │
│ Settings   │                                       │              │
├────────────┴───────────────────────────────────────┴──────────────┤
│ Now-playing bar: cover · title/artist · ⏮ ⏯ ⏭ / seek ⟳ · vol · queue│
└────────────────────────────────────────────────────────────────────┘
```

- Sidebar ~220px, queue ~320px (collapsible), bar ~76px. Minimum window 900×600.
- **Repeat** is an icon toggle right of the timeline's total time (in the bar and in Now Playing): off is a muted icon, all the accent icon, one the accent icon with a "1"; its tooltip names the current mode and the next. `r` cycles it too; there is no notice for it.
- The **queue header** has icon buttons (with tooltips): Shuffle upcoming (shuffle), Save queue as playlist (playlist with a plus; only with Navidrome set up) and Clear queue (a broom; asks first).
- **Window (macOS)**: no separate title bar. The native close/minimise/zoom buttons are inset at the sidebar's top-left, in a 40px row above the source switch (over the backdrop's top-left in Now Playing); they show their glyphs on hover and grey out when the window is inactive, like any Mac app, and macOS hides them in full screen (no row kept then). The page header, the queue header, the sidebar's top row and Now Playing's top band drag the window (double-click zooms); their buttons and fields work as usual. Linux keeps the window manager's title bar.
- **Now Playing** (`f`) is immersive: the sidebar, browse area, queue column and the bar are hidden; only the view remains. Large cover, title/artist/album, one timeline (repeat beside it), one transport row (previous / play-pause / next, volume on the right), visualizer bars and a small **Up next** card (cover, title, artist; clicking it opens the queue; while the queue is open it fades out but keeps its place, so the info does not jump down). Background a heavily blurred, darkened copy of the cover. Top right: lyrics, queue, a Full screen / Exit full screen toggle and Close (Esc or `f`). `f` and the bar's Full screen button (right of the queue button) open it in full screen; a click on the bar's cover opens it windowed. Closing it leaves full screen only if opening it (or its toggle) entered it. The queue opens as a translucent ~360px side panel sliding in from the right (`q` or the queue button): the same queue (selection, drag-and-drop, header buttons), its open/closed state remembered apart from the main layout's. Wide windows make room for it; narrow ones let it overlay. All global shortcuts keep working.
- **Lyrics mode** (`l` inside Now Playing, or the toolbar's lyrics button left of the queue button; tooltip "Lyrics (l)", the button shows its on state and its label names it). On for the session once turned on (across track changes and closing the view), off at launch. The player stacks into a column on the left (~300–340px: cover at most the column's width, title, artist · album, timeline and repeat, transport with volume, visualizer, Up next); the lyrics fill the middle, at most ~40ch wide, centred, fading out at the top and bottom edges; the queue panel slides in over the right of the lyrics area at any width, so neither the column nor the lyrics move; only when the text would be under the panel does it move left (and in narrow windows wrap narrower, down to 18ch) just enough to clear it. There is no stacked layout: the minimum window width (900px) always leaves room for the column beside the lyrics. Timed lyrics follow the song: the current line in the text colour, the others dimmed (colour only, no size change, so nothing moves), kept about a third of the way down with a smooth scroll; any scroll the view did not make itself (wheel, touch, keys, dragging the scrollbar) pauses that for ~4 s (with the queue open the scrollbar is under the panel; wheel, touch and keys still scroll), then it eases back, never while the scrollbar is held; clicking a line seeks there; lines are not Tab stops. Untimed lyrics are plain text to scroll. A track without lyrics keeps the layout and shows a dim "No lyrics for this track"; a failure "Couldn't load lyrics"; loading shows nothing for 300 ms, then a quiet "Loading lyrics…". While paused the highlight stays. Switching layouts glides the cover and info into place and fades the lyrics in after (Motion below); with reduced motion nothing animates and scrolls jump.
- **Search**: the box's placeholder reads "Artists, albums, tracks or lyrics in the local library" (Navidrome: "… in Navidrome"). Below Artists, Albums and Tracks comes a **Lyrics** section (local, and Navidrome while its lyrics index is on): track rows like the Tracks table (title with artist below, album column, time, "…"), 58px tall with a third, dimmer line (`--text-3`, small) holding the lyric line or the two lines the match spans (joined by " / "), the matched phrase in `--text` at weight 600 (no highlight colour). It appears only once loaded (no spinner), never for queries under 3 characters, and ends with "and N more" past 50 matches. On Navidrome, whenever songs are left to index (building, before the launch sync, paused), a quiet secondary note follows the results: "Lyrics are still being indexed (1,200 of 2,400 songs)"; while the index is still loading: "The lyrics index is still loading."
- **Settings › Navidrome › Lyrics search** (shown when a server is set up): a small heading, the switch "Index lyrics for search — kept on this computer, so Navidrome lyrics can be searched" (on by default), and while on, a settings row with the status in secondary text ("Loading the index…", "Indexing… listing albums", "Indexing… 1,200 of 2,400 songs" — songs checked of all songs, the same counts as the search page's note — "2,341 songs indexed · up to date", "Paused: couldn't reach the server · N songs indexed") updated live, and a **Rebuild index** button (disabled while a sync runs). The block is a labelled group; the counts are not announced as they change, a hidden status line announces only state changes ("Indexing lyrics", "Lyrics index up to date", …). The switch shows its new value at once. Errors show as the usual red status line.
- **One source at a time**: a segmented switch "Local | Navidrome" (with icons) tops the sidebar when both are configured (`Ctrl/Cmd+1` Local, `Ctrl/Cmd+2` Navidrome); with one source there is no switch, only its name and status. Below it one set of entries for the active source: Home, Search, Albums, Genres, Artists, Playlists, Folders (local only); Settings at the bottom. **Genres** lists the source's genres A–Z with album and track counts; a genre opens its albums as a grid with Play and Shuffle (Navidrome: Shuffle only, random songs of the genre; `s` shuffles the genre). An album page shows its genres as small tags under the title that open their genre pages. The choice is saved in `~/.config/coda-app/settings.toml` (default: Navidrome if configured, else Local; a source that goes away falls back to the other). Search searches the active source, with a "Search … instead" link. The queue stays mixed; only browsing is per source, and "Go to album/artist" on a track of the other source switches first.
- **Mixes** (M12; sidebar entry after Playlists, a two-circles icon): the source's saved mixes as cards in a responsive grid (≥280px): the name, the ingredients as small chips (kind icon — tag, person, disc — then the name; an album adds " · artist"; at most 8, then "+N more"), a primary **Play** and a "…" button. Right-click, "…" or the context-menu key opens Play, Edit… (F2) and Delete… (Delete; a danger confirmation). The playing mix's card has an accent border and a "Playing" tag ("Loading…" while its songs load). The header has **New mix…**; with no mixes the empty state says in one line what a mix is. **The editor** is a dialog (~540px): Name (placeholder: a name made from the first ingredients, used when left blank), then "Genres, artists and albums" with an "N of 50" count, the chosen ones as removable chips, and one search field (combobox): after a short pause it searches the source's genres, artists and albums together and lists up to six of each (names starting with the query first) with their kind icon and label; ↑/↓ move, Enter or a click adds (and clears the search), Esc clears the search (a second Esc closes), Backspace in an empty search removes the last chip. Errors (a full or invalid mix, another server, a newer file) show inline in a soft danger box; the dialog stays open. Buttons: Cancel, **Play** (a quick mix, not saved) and **Save** (primary). Editing a saved mix notes "Changes apply the next time this mix plays." **Add to mix…** (genre and artist row menus, the album menu, and a button on genre, artist and album pages) opens a small picker like Add to playlist: a filter, "New mix with this…" first (the editor, prefilled), then the source's mixes ("Already in it" or "Full" where so); picking one adds it and says so in a toast. While a mix is active, Now Playing shows "Mix: <name>" (or "Quick mix: <name>") above the title and the queue a line under its header, with the accent mix icon; while its songs load the line is dimmed with a pulsing dot and "Loading…".
- Navigation keeps a back stack **per source** (switching back shows where you were; Back with `Backspace`/`Alt+←`/mouse back button): Home → Artists → Artist (albums) → Album (tracks).
- **Home** (each source's landing view): calm "Home" header, then rows of ~160px cards (cover, title, kind · artist), each row scrolling sideways with ‹ › buttons: Recently played (the latest distinct albums, artists, playlists, folders played as a context), Most played (Navidrome: the server's most played albums, then playlists by our listen counts; Local: albums and playlists by our counts), Recently added (Navidrome), Daily Picks (12 albums, the same all day, new at local midnight) with "Shuffle Daily Picks". Empty rows are hidden; a new user sees a one-line hint, Recently added and Daily Picks. Click/Enter opens a card, its hover ▶ button or Shift+Enter plays it; ←/→ move within a row, Tab between rows; `s` shuffles the Daily Picks.

## Visual language
- Every colour is a theme token (see Theming). The default look, the built-in **Coda** theme: dark first (`#0f1012`-ish background, raised surfaces a few steps lighter); **Coda Light** for a light system appearance.
- One accent colour (Coda: warm amber, ~`#f0a83a`) for the playing track, progress, focus rings and primary buttons. Everything else is the theme's neutrals.
- Typography: system UI font stack (`system-ui, -apple-system, "Inter", "Cantarell", sans-serif`); tabular numerals for times and track numbers. Sizes: 13px body, 12px secondary, 20–28px view titles.
- Covers: rounded 6px corners, subtle shadow; album grid tiles ~180px with title and artist below; a generated placeholder (initials on a gradient of two of the theme's cover colours, picked from the album name) when there's no art.
- Track tables: #, title (with artist below when mixed), album, duration; the playing row shows an animated equaliser glyph in the accent colour. Row height 36px.
- Motion: short (120–180ms, `--motion-fast`/`--motion`) and subtle for hover, colour and small state changes; ~300ms (`--motion-slow`, 320ms) eased (`--ease-out`, `--ease-in-out`) for Now Playing's large moves. Only `transform` and `opacity` animate (never layout properties, so text never rewraps mid-way), and nothing holding focus or state is remounted for it. With `prefers-reduced-motion: reduce` nothing animates (CSS and Web Animations alike). Now Playing:
  - **Opening** the view fades it in and scales it up slightly (0.98 → 1); closing is instant.
  - **Queue panel**: slides in from the right and out again (a reopen mid-way turns it around); the leaving panel is inert, and focus inside it moves to the view. Where the layout changes with it (wide windows make room; 1180–1500px the content stacks), the cover and info glide to their new place (FLIP: transforms from the old place to the new); the main layout's queue column slides in and out too (while it leaves, the main view has its room back at once and the column slides out over it).
  - **Up next** fades out (with a small drop) while the queue is open and back in after; a new next track fades in.
  - **Lyrics mode**: the cover and info glide between the centre and the column, then the lyrics fade in; the lyrics also fade in when they load (or turn out missing or failing) and on a track change.
  - **Track change**: only the cover and the title lines (mix line, title, artist — album) slide: the next track (also when repeat all wraps to the start) or a later one in the queue sends the old ones out to the left and brings the new ones in from the right, an earlier one the other way; a track not in the queue counts as later; restarting the same entry does not slide. The timeline, transport, volume, visualizer and Up next stay put; the backdrop crossfades; in lyrics mode the lyrics fade. It waits up to ~150ms for the new cover to decode. Quick presses interrupt cleanly from wherever the slide had got to. Opening the view on a track does not slide.
- Icons: inline SVG (one small icon set in `src/components/icons.tsx`), 16–20px, `currentColor`.

## Theming
Terminal-style palettes, read straight from **Ghostty theme files**, so every theme the owner already uses in Ghostty works here.

- **Sources** (merged by name, later wins; the picker shows each one's source): built-in (Coda, Coda Light, Kanagawabones, Kanso Zen, Kanso Pearl, Catppuccin Mocha, Catppuccin Latte; credits in `src-tauri/themes/THEMES-CREDITS.md`), Ghostty's installed themes, the user's `~/.config/ghostty/themes`, and the user's own `~/.config/coda-app/themes/` (custom; `$XDG_CONFIG_HOME` respected).
- **Theme file**: Ghostty's keys (`background`, `foreground`, `palette = N=#rrggbb`, `selection-*`, `cursor-*`), plus optional Coda keys Ghostty ignores: `coda-accent = #rrggbb` or `palette:N`, and `coda-<token> = #rrggbb[aa]` for any token below (`coda-surface`, `coda-border`, `coda-danger`, …), and `coda-explicit = …` naming the colours the user chose (the editor writes it; those are never adjusted for contrast).
- **Tokens**: a theme sets a few base colours: `--bg`, `--fg`, `--accent` (default palette 3, else 4/5 when 3 is too faint), `--danger` (palette 1), `--selection`, `--palette-0..15`. Everything else is derived by mixing in OKLab: surfaces 1–3 and border step from the background toward the text (light themes keep raised surfaces a touch whiter), text-2/text-3 fade toward the background, hover/selected are translucent text, accent-soft/danger-soft are translucent accent/danger, shadows are darker on dark themes, accent-text/danger-text are black or white by contrast, the Now Playing view stays dark over the blurred cover, cover placeholders are palette 1–6 darkened, the visualizer uses the accent (or palette 1→6 across the bars). `<html data-scheme="light|dark">` comes from the background's lightness.
- **Contrast**: body text ≥4.5:1 on the background and every surface, secondary text ≥4.5:1, faint text, accent, danger and success ≥3:1. Computed colours (and the colours of themes the user did not write) are nudged in OKLCH lightness until they pass; a colour the user set is never changed, it shows a small contrast warning instead.
- **No colour literals outside the token layer**: components and stylesheets use `var(--…)` only; the hex values live in `src/styles/tokens.css` (the built-in Coda themes, as fallbacks) and in theme files. `pnpm build` fails otherwise (`scripts/check-colors.mjs`).
- **Settings → Appearance**: mode (one theme; light + dark following the system; follow Ghostty's `theme = …`, incl. `light:A,dark:B`, re-read when the window regains focus), a searchable list of every theme with a swatch strip (background, text, accent, palette 1–6) and a source badge; moving through it previews live, Enter/click applies, Escape reverts. An accent picker (palette swatches, custom hex, reset to the theme's), the visualizer's colours, "Reveal themes folder", and Duplicate / Rename / Delete (custom themes; delete asks first). Saved in the GUI's own `~/.config/coda-app/settings.toml`, not Coda's `config.toml`.
- **Customise colours**: every base colour and derived token, grouped in plain words ("Sidebar & panels", "Secondary text", …), each with a swatch, hex field, colour picker and Reset; derived ones show their computed value until set. Edits preview live. Saving writes a custom theme (default "<Theme> (custom)", renameable) as a Ghostty file with `coda-*` keys for the overrides, and selects it; built-in and Ghostty themes are never changed.
- The chosen theme is applied **before the first paint** (the backend injects its tokens when it creates the window), so there is no flash of the default theme.

## Interaction
- Double-click or Enter on a track plays its context (album/playlist/list) from that track. Context menu: Play, Play next, Add to queue, Go to album, Go to artist, Add to playlist.
- Artist and album names open their page on click wherever an id is known (track rows, the queue, the now-playing bar and view, album and Home cards): plain text that turns the accent colour on hover, no underline, default cursor. In rows and cards a click on a name does not select, play or drag the row, and adds no Tab stop (the menu has Go to album/artist); in the bar and Now Playing they are Tab stops (Enter). Names without an id stay plain text, and so does a local track's artist when its album artist differs (the id is the album artist's; the menu still offers it). The Up next card's names are deliberately not links (the card is one button that opens the queue).
- Keyboard (global, unless typing in an input): `Space` play/pause, `n`/`p` or `Ctrl+→/←` next/previous, `←/→` seek ∓5s, `+`/`-` volume, `r` repeat, `s` shuffle context, `q` toggle queue, `f` Now Playing (full screen), `l` lyrics mode (in Now Playing), `/` or `Ctrl+F` search, `Ctrl/Cmd+1`/`2` Local/Navidrome, `Esc` close overlay/back.
- Errors and notices (player messages, Navidrome failures) appear as small toasts bottom-right above the bar; persistent problems (mpv missing, Navidrome unreachable) as a banner in the main view.
